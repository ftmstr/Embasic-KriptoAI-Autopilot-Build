## 2. New and non-duplicative RC692 threat model

[New offline source](../safe_public_ci/ci_chain_of_custody_quarantine.py) defines a *bounded* caller-asserted chain of custody rather than a verified Ed25519 signature or network provider. Typed, exact-field checks include:

This explicitly does not prove independent distribution of either public key or authenticity of a claimed signature or trusted time.
- Two different alleged OS providers (`ubuntu`,`windows`) with claimed run/job identifiers, exact repo/branch/source/workflow pins, full-job-log digests, job digests, claimed signed receipt digests/signatures and separate asserted controller names. No real GitHub-signed provider receipt or out-of-band key source is fetched or verified. Metadata and hashes may be copied/fabricated by a single adversary.
- RFC6962-domain-separated Merkle hash **math**, exact prefix consistency from bounded caller-provided full leaf history (2–128 leaves), a leaf inclusion path, and strict old/new root. A mathematically consistent claimed root does not establish an externally committed, append-only, immutable timestamped checkpoint.
- Three self-declared witness domains/controllers and all six directed peer-to-peer gossip claims. Pairwise independent-looking labels cannot show genuinely independent administrators, and the records come exclusively from the caller. Structural checks reject false roots, epochs, missing/duplicate edges, invalid encoding and purported privilege elevation.
- A local expected-generation → next-generation fence and token, nonce digest, PENDING outbox and explicit **no** signed ACK, provider-seen, or external-CAS verification. Local state is not production CAS; no remote monotonic or privileged-rollback-resistant service exists.
- Explicit `authenticated/live/final/fitted/net20_tested=False`. `validate_claim` can only return `QUARANTINED_CLAIM_ONLY_NOT_AUTHENTICATED` and explicit `False` for real origin/authentication/production CAS/remote ACK/release/live. `compare_views` classifies *claims* into same-epoch Merkle forks, provider full-log forks, witness receipt forks, nonce ABA replay, build pin forks, different epoch or equality; none grants authority.

The module has **no** file access, cryptographic signing, network/API calls, SQLite dependency, exchange integration or model training. The only imports are `hashlib`, `hmac`, `re`. AST prohibited direct calls `open`, `compile`, `eval`, `exec`, `__import__` are absent. Real Ed25519 public keys, a trusted distribution path, provider-signed run/job/full-log artifact, verified revocation chronology and external signed immutable checkpoint were NOT supplied and are NOT manufactured.

### Security conclusion

The synthetic claim checker and test-only local SQLite unit have **zero actual trustworthy external authority**. Local transaction correctness cannot prevent the privileged owner from snapshot-restoring the database, fabricating a local checkpoint, or creating two disconnected winning copies. A pending or locally marked ACK cannot distinguish a remote order never received from one received but whose response was lost. None of these tests perform any real exchange order or assert an exactly-once exchange side effect; there is **no integrated production durable multi-host CAS**, authenticated provider receipt, independently notarized Merkle checkpoint, authentic independent Ed25519 owner/reviewer trust or true remote ACK recovery.
