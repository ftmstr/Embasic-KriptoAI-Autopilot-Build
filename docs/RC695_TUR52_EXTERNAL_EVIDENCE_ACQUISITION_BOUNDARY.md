## New concrete integration deliverable

`safe_public_ci/ci_rc695_external_acquisition_boundary.py` introduces a type-specific, exact-source/challenge/epoch, real-hosted-run/job/attempt-scoped **eight-slot acquisition request**. The eight proof types identify external owner/reviewer independent Ed25519 authority, provider-issued complete Ubuntu/Windows job log signature, trusted clock with revocations, immutable Merkle root, truly remote multi-host linearizable CAS, and a remote signed idempotent ACK. The module does NOT obtain or verify these items. An observation intake can only yield `QUARANTINED_CLAIMS_NOT_EXTERNAL_PROOF`, never `authenticated=True`. Distinct claimed controllers/domains, digest-shaped signatures, caller-designated trust roots, job metadata or a locally replayed ACK do not prove any real independent authority.

New explicit classifier rejects fake quorum/Sybil claims, stale/replayed challenge and duplicate nonce, wrong full-log/job/attempt identity, false provider-signed status, false signature authorization, and malformed exact envelope. It detects contrary Merkle gossip roots, multi-host generation/fence conflict, snapshot rollback, privileged ABA or contradictory payload claims and lost-ACK ambiguity, yet never elects a trusted winner from the observations alone. `reconcile_remote_ack` implements an exact-idempotency/fence **structure** check only; even matching signatures claimed locally leave the outbox PENDING. There is no database/network/exchange/credential access, production API integration or real cross-host CAS.

**Integration requirements**: independently delivered pinned Ed25519 public keys and roles; a real externally audited verifier of provider-signed original FULL-log bytes (GitHub run success alone is not this proof); authenticated revocation chronology; independently witnessed append-only Merkle history; remote fault-domain-separated monotonic CAS/fencing that cannot be rolled back by local privilege; recipient-signed idempotency reconciliation with lost-ACK recovery. A caller-supplied `verified` flag is categorically rejected. 0/8 real external evidence gates remain BLOCKED until these are actually acquired and audited.
