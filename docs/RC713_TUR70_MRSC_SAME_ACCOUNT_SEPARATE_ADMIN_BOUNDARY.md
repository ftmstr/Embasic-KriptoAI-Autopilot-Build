## Newly verified AWS provider incompatibility: separate admins is NOT multi-account MRSC

AWS [DynamoDB multi-account global tables](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/globaltables-MultiAccount.html) explicitly states **multi-account global tables offer only MREC; MRSC does not support the multi-account model**. AWS [Global tables](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/GlobalTables.html) specifies MRSC is **same-account only**, and consistency mode cannot be changed on an existing table. Therefore the user's independently administered control requirement must NOT be implemented by placing *MRSC replicas across different AWS accounts*. Cross-account replication is MREC with different failure and last-writer-wins semantics. The future independent-admin OOB signing/custody and AWS IAM roles are an *authorization separation requirement*, different from the DynamoDB replication account topology. Even different IAM roles in one AWS account would still require separately obtained external independent verification and anti-restore evidence.

This is a materially new operator acceptance risk not covered by RC709 Rekor v2 `integrated_time=0`, RC710 populated PITR-to-MRSC conversion ban, RC711 MRSC TTL-fencing ban, or RC712 MRSC Streams/CloudWatch/witness versus application-ACK firewall. Existing controls remain unchanged.
